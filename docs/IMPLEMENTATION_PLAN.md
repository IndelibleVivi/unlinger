# Unlinger 0.1 implementation plan

**Current source and installed tranche:** SQLite v11 adds a durable chrome
code-sign-clone cleanup result authority on top of the v10 session-owner boundary: a
PREPARED attempt row written before any clone-directory deletion, one terminal
result committed in the same transaction as the real latest residue
observation, bounded in-process recovery to `delivery_unknown`, and an additive
optional schema-v5 result summary carrying only a typed outcome, timestamps and
aggregate counts/logical bytes. Generation 35 migrated v10→v11, passed App/socket
and restart checks, and really rolled back to generation 34 reopening v10. The
same exact `a9355fa` backend artifact was freshly installed, accepted and armed
as healthy `ReadyEnforce` generation 36 with SQLite v11 and no rollback lease.
The installed App carries the cleanup-result UI and native-popup memory repair;
rendered QA found and fixed one missing bilingual clear-detail key plus stale
root navigation titles, exercised Home/History/Settings, and a 180-second
Settings/Accessibility RSS guard reached a 37,520 KiB maximum without a growth
trend. Historical generation 34 supplied
the bounded 9→1 clone cleanup while ordinary Chrome stayed open, but no clone
deletion has yet occurred under generation 36. These transaction, UI and bounded
memory facts are not v11 live-result, ambient process-cleanup, physical APFS
reclaim or multi-day acceptance.

## Scope/order notes

- **Schema v2 is historical, not a compatibility endpoint.** It never reached the installed service or a public release, so v3 replaces it without a downgrade path while its fixtures remain as audit evidence.
- **Frontend receipt authority is App-scoped.** Schema-v3/v4/v5 mutation behavior shares the durable receipt contract; schema-v1 CLI/service ordinary behavior remains compatible; lifecycle commands never enter frontend schemas.
- **Notifications are bounded and best-effort.** Duplicate avoidance is preferred: durable claim occurs before one OS schedule attempt. A mode change never replays suppressed history. Ambiguous count/CPU/RSS/age/pressure has no notification authority.
- **BGX-1 changed presentation only and is now historical source groundwork.** BGX-2 is the authorized successor source tranche: it may change the frontend protocol and rule-derived public projection, but it must not widen detection or cleanup admission, replace the installed service, or change report-only mode.
- **V4 and v3 remain real compatibility boundaries.** Existing requests retain their response schema and meaning; the source App emits v5 only, schema v2 remains rejected, and lifecycle commands remain absent from every frontend schema.
- **Task release and activation remain separate.** TASK-01 records command lifetime through operator IPC; the frontend overview still contains no task/lifecycle mutation or activation authority.
- **Optional host ownership is evidence, not a new cleanup authority.** HOST-01 keeps the ordinary Playwright session name, exact registry namespace and controller version; unsupported, absent, active, reused or unproved ownership stays protected. It does not satisfy the install-and-forget product contract until a supported host itself supplies exact task/thread-to-controller binding and drives reserve/activate/release. Turn-level hooks, external observers and `session run` wrappers do not meet that zero-touch contract. Controllerless core cleanup remains integration-independent.
- **Runtime-artifact capability remains DAP-only, and current admission is none.** Source and installed packs suppress every DAP candidate while preserving the dormant implementation and both P2 residuals for a separate decision. Chrome clone cleanup is a separate storage-residue family with its own exact-root/process/stability gates; it neither enables nor reuses runtime-artifact authority.
- **The installed claim is narrow.** Generation 23 has its own rollback/reinstall/App evidence, active generation-bound enforcement and a controlled task-owned CfT-152 receipt with actual App impact. It does not establish an ordinary ambient incident, multi-day behavior or complete current-generation managed restart/containment harness acceptance.
