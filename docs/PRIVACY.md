# Privacy

Unlinger is local-only and has no account, telemetry, cloud sync, hosted report, remote rule fetch, or normal-operation network traffic.

Process arguments and executable paths can contain usernames, repositories, profile names, URLs, ports, and tokens. The macOS backend reads them transiently because exact classification, debug-peer checks, runtime-artifact reference checks, and app-bundle ownership require those facts. Exact bundle identifier/version is read from the owning app's bounded `Info.plist` without invoking a shell. DAP reference proof asks Darwin whether any process holds the one exact canonical or quarantine pathname and separately reads current-user `KERN_PROCARGS2`; it does not enumerate or persist the unrelated pathname contents of every same-UID process's file-descriptor table. Raw paths and arguments remain inside the in-memory snapshot/analyzer/cleanup boundary.

Current source uses SQLite v13; the reference installation remains generation 36 on SQLite v11. The dated installation and rollback evidence is owned by [`current-state.md`](current-state.md), not re-verified by this source task. The schema persists typed redacted observation spans, cleanup receipts and independent cleanup impacts, mutation receipts, stable opaque public event/receipt-authority tokens, durable policy revision, and lifecycle state: incident IDs, signature-pack ID/version, process roles and counts, basenames, resource totals, evidence IDs, hard-gate values, redacted fingerprints, signal stages/dispositions, artifact kind/disposition, bounded outcomes, tracking completeness, and generation/epoch state. SQLite v9 archives the pre-v9 cumulative impact authority once as bounded private JSON and rebuilds the public proved-reclaim projection only from retained cleanup attempts with durable delivered-signal evidence; v10 composes that migration and adds optional session-owner tables; v11 adds path-free Chrome clone cleanup attempt/result authority. The archive is migration provenance, not a public receipt or a new source of process/path identity. The schema does not serialize raw argv, executable paths, profile or artifact paths, app-bundle product/version facts, frozen target identities, tracking keys, or session fingerprints into user-visible history. Typed browser product/version compatibility exists only on the current in-memory report and schema-v5/v4 browser overview; it is deliberately skipped by persisted observations. Cleanup impact stores only aggregate terminal/proved counts, proved process count and measurement-complete estimated memory totals; it cannot reconstruct process identities or deleted paths. Cooling, retry, exact-incident protection, artifact-action, frontend mutation, and managed-lifecycle tables retain only the redacted identifiers, canonical ordinary arguments and timestamps needed for their safety contracts. An artifact journal accepts a bounded `art-...` fingerprint and rejects path-like input before writing.

Task ownership, introduced in SQLite v8 and retained unchanged by current source v13, adds private task/capability, registrar and actual command-owner PID/birth/UID, controller PID/birth/executable identity, timestamps and incident links. These are lifetime safety records, not serialized signal plans or public history. Only the issued `PLAYWRIGHT_CLI_SESSION` selector is retained from the environment; all other environment bytes are discarded. Exact CLI registry/package files are read transiently with bounded owner-owned/no-follow checks, and socket paths become transient fingerprints. Task status omits capabilities and owner/controller identities. No command text, workspace path, profile path, registry path or raw environment is persisted. Released records expire after at least 14 days and proved absence; impact retains its independent authority. See [task semantics](TASKS.md).

SQLite v10's optional host session-owner lane stores a fresh private lease ID/capability, a path-free fingerprint derived from the Playwright registry's 16-hex namespace and unchanged session name, exact controller version, lease generation, registrar/owner PID-birth-UID identities, activation/release timestamps, release reason and exact bound controller executable identity. The namespace is not a workspace path, and neither the workspace, registry path, socket path, command, raw environment nor host conversation/task identifier is persisted. Registry/package JSON is read transiently under owner/no-follow/size bounds; the controller's socket pathname becomes only the existing transient fingerprint. Status omits capability and native identities. Frontend v3/v4/v5 exclude all session-owner commands and payloads. Released records require both the 14-day minimum and complete exact-identity absence before pruning.

The source storage-residue path accepts only the exact current-user Chrome `code_sign_clone` family and persists one typed latest observation: kind, observation time, bounded entry count, logical bytes, aggregate reference completeness, automatic-cleanup eligibility and typed reason IDs. It never persists or publishes the root pathname, clone child names or file contents. Prior exact candidate identities used for each candidate's 15-minute stability gate exist only in daemon memory and are discarded on restart. Native executable paths and arguments used to prove candidate-level path/suffix references remain within the existing transient process snapshot. The public aggregate may truthfully combine `reference_check: referenced` with `automatic_cleanup_eligible: true` when a protected candidate coexists with an eligible unreferenced candidate; neither field discloses which child is involved. Logical size is not presented as physical disk space guaranteed to be reclaimed.

SQLite v11 adds one internal storage-cleanup attempt row before any admitted clone-directory deletion. It stores only an opaque internal token, prepared/completed times, typed disposition and aggregate planned/before/removed/after/retained counts plus logical-byte sums. The schema-v5 public summary omits even that internal token and exposes only the outcome, timestamps and aggregate measurements. Neither durable surface contains the root path, candidate names, argv, user name or raw candidate identity; `delivery_unknown` records uncertainty without reconstructing attribution from a later observation.

The canonical per-user source layout stores history, service manifests/transactions, rollback evidence, generation directories, locks, and the runtime socket under `~/Library/Application Support/Unlinger/`; the socket and daemon lock live in its `run/` subdirectory. One stderr log lives under `~/Library/Logs/Unlinger/`, and the service definition lives under `~/Library/LaunchAgents/`. Writable private directories use mode 0700. Published generation directories and binaries are sealed 0500, generation manifests are 0400, and mutable service files, database/backup, locks, socket, plist, and log are 0600. The LaunchAgent applies umask 077. Successful cycles write nothing to the service log, and repeated identical cycle errors are emitted once until recovery rather than once per sweep.

The owner-private newline-delimited JSON IPC socket is bounded and schema-versioned. Frontend schemas v3/v4/v5 contain only public status/history/explain/roster/mutation-status/diagnostics and ordinary pause/resume/retry/protect/unprotect commands; v4/v5 additionally contain one read-only atomic browser overview and rule-generated support catalog, and v5 adds impact/residue/span facts. Generation-and-instance-bound `Arm`, `Disarm`, and `BeginDrain` do not exist in any frontend enum. Their DTOs remove raw/survivor/source PIDs, internal event/attempt IDs, process/member/artifact fingerprints, daemon instance/generation/epoch, database schema, raw errors, service transaction facts and path identities. V5/v4 browser compatibility exposes only a bounded product enum, optional version string, decision and stable reason ID from the already-required transient app-bundle observation. Public event tokens and mutation namespace/UUIDs are opaque local correlation values, not account or machine identities. Schema v4 is transitional, schema v3 is legacy-compatible, schema v2 is historical and rejected, and schema v1 remains the local Rust CLI/service compatibility and diagnosis surface with bounded internal identities.

Clients make one attempt and never automatically resend a timeout. The App writes canonical pending intent before connect/send to `Library/Application Support/Unlinger/app-state/pending-mutation-v1.json`; notification dedupe state uses the same private directory. The directory is owner-only `0700`; files are exact owner-owned regular `0600` files written through fsync + atomic rename + parent fsync. Pending state contains the public namespace token, UUID, ordinary mutation kind/arguments, semantic lock, time and visual-dismissal flag. Notification state contains public event tokens, bounded claim/episode timestamps and authorization summary. It contains no raw process/path/browser contents. Current OS notification authorization remains authoritative over the stored summary.

The App requests local notification permission only from the packaged live mode. Fixtures, previews and tests use fake schedulers and do not call the real notification center. Notifications have no sound and carry only route kind, redacted incident ID and public event token in `userInfo`; they do not carry reason text, raw backend identities or mutation journals. The feature is local best-effort delivery, not telemetry or a hosted push service.

Up to eight accepted IPC connections are served concurrently and each retains a 3-second I/O bound. Frontend diagnostics combine only public status and public incident detail, require the exact requested document schema version, and are semantic-lossless rather than byte-verbatim; explicit CLI v1 export remains owner-private and more diagnostic. The v5/v4 recent-settlement join runs on durable event identity and returns only public family/count/resource/outcome fields.

A diagnostic output file uses 0600, rejects unsafe/non-regular targets, and refuses replacement unless the caller explicitly passes `--force`. `service uninstall` removes only managed service definitions and binaries/generations; it deliberately preserves local history and logs. A failed generation can preserve owner-private database evidence for recovery rather than discarding it silently.

Current source and installed process-only packs disable runtime-artifact admission, so ordinary enforcement produces no DAP candidate and no artifact journal row. The dormant cleanup engine can remove at most one exact `DevToolsActivePort` regular file only when a future active pack explicitly enables it and all tree, revival, reference, identity, and quarantine gates pass. Only its redacted fingerprint and disposition may enter history. Separately, current source may remove only the exact validated Chrome code-sign clone candidate directories under its current-user root after its storage/process/lifecycle gates. No process-reconciliation or storage-residue path deletes profiles, browser data, sockets, PID files or other runtime directories.

The artifact implementation remains deliberately labelled partial and dormant. A daemon crash after the canonical entry is atomically renamed can leave the exact random quarantine entry in the private profile, and the final `fstatat`-to-`unlinkat` interval retains a same-UID swap TOCTOU. Neither residual exposes the path remotely or authorizes deletion. Exact DAP removals passed in controlled generation-9 and generation-13 runs, but both residuals prevent re-enabling the current packs without a separate decision.

The first activated-host inspection found no IP socket owned by `unlingerd`. This is point-in-time host evidence consistent with the no-network design, not a substitute for longer runtime observation.

Fixtures use synthetic paths and identifiers. Page contents, browser history, cookies, credentials, application conversations, saved authentication state, and the private origin conversation are outside the observation and repository contracts. Runtime operation does not inspect page contents or browser storage.

Private working continuity and live/private captures stay outside Git. Repository privacy does not make them safe to commit. Before any public visibility change, tracked content must be scanned again for machine paths, personal identifiers, raw captures, private provenance, secrets, and unsupported product claims.

## Tool-cache maintenance records

Source SQLite v13 retains one latest uv cache observation/attempt and separate
retired v12 npm evidence: typed
availability/outcome, timestamps, aggregate native counts/logical bytes and an
internal random settlement token. The v5 projection omits that token. Cache
paths, package keys, digests, contents and raw stdout/stderr are not persisted or
sent over IPC. Native output is bounded in transient memory and only typed
numbers are retained. The adapter uses a fixed installed native executable and
cleared execution environment; it neither sends telemetry nor fetches packages.
No credentials or producer configuration are read to discover custom caches.
