## Source truth

The backend source now uses SQLite schema v7 and accepts frontend schemas v5, 4 and 3 while preserving schema-v1 CLI/service compatibility. Schema v5 is the source App contract. It extends the daemon-owned atomic browser projection with cleanup impact and typed storage residue and adds observation-span fields to history/detail. Schema v4 retains the prior atomic overview shape without v5-only fields; schema v3 retains its existing response meaning and rejects `browser_overview` without downgrade. Schema v2 remains historical and receives typed `unsupported_schema`. The source App emits v5 only and never falls back to v4, v3 or v1.

All source and installed rule packs are policy version `0.4.0`. They add only exact CfT `152.0.7977.42` beside the existing `151.0.7922.34` allowlist point; every nearest wrong version remains protected. Existing protection gates, timing, revalidation, TERM/KILL sequence, revival handling and durable process-action journal are unchanged. Every pack still sets `devtools_active_port = false`, so analysis produces no runtime-artifact candidate. A supported browser version is not sufficient by itself: the currently observed CfT 152 session remains protected because its controller version is not independently verified. The existing DAP engine and its focused tests remain dormant for a future explicitly authorized residual-resolution lane.

Frontend ordinary mutations carry a public-safe namespace token plus canonical UUID. The daemon serializes lifecycle state with a `BEGIN IMMEDIATE` store transaction, replays an exact stored receipt before current lifecycle policy, re-evaluates authoritative durable facts through one shared public-action policy, applies state, advances a durable cleanup-policy revision and stores a typed `applied | no_change | rejected` receipt atomically. Same-ID canonical replay is idempotent; conflicting reuse fails; old-namespace missing requests cannot apply. Receipt pruning rotates namespace atomically and retains a minimum 14-day reconciliation window.

SQLite v7 retains the v6 event/recovery/mutation authority and changes history storage in two deliberate ways. Consecutive semantically identical observations for one incident extend one row with first/latest time and count; RSS updates but does not split a span. Cleanup terminalization atomically writes a separate impact row and advances a lifetime aggregate that observation retention cannot evict. Observation age/count limits apply only to observation rows; cleanup impact/detail remains for at least 14 days and aggregate totals survive detail expiry. A v6 migration backfills what can still be proved and labels totals `partial_backfill`; a fresh v7 database labels them `complete`.

The source daemon also samples the exact current-user `X/com.google.Chrome.code_sign_clone` family no more than once per 15 minutes. It accepts only the expected clone-name/app-bundle shape, sums regular-file logical sizes, rejects symlinks/unreadable/unexpected trees, persists no path or file content, and always records `automatic_cleanup_eligible = false` because live-reference proof is incomplete. Missing residue is a typed clear observation; detected logical size is not claimed as APFS physical reclaim.

Typed browser product/version compatibility remains transient and is not persisted in observations. `RuleSet` generates the public family/product/admitted-version/action-level catalog from embedded version policies with a readable support revision. `ControlPlane` captures status and roster under one in-memory boundary, then `public_ipc` produces phase, current session summaries, typed coverage, attention/protection, impact/residue and recent settlement. Untrusted readiness/freshness/time becomes `unknown`; trusted phase precedence is server-owned. Recent settlement resolves its exact durable impact by public event token, so later failed attempts or bounded-history pruning cannot hide or cross-wire the most recent proved process reclaim.
